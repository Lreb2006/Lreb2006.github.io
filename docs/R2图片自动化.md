# R2 图片自动化

本机 `.env` 配置 R2_ENDPOINT、R2_ACCESS_KEY_ID、R2_SECRET_ACCESS_KEY、R2_BUCKET、R2_PUBLIC_URL。使用 R2 的 S3 密钥，Secret Access Key 不是 API 令牌值。密钥不提交。

## 日常写作

在 PicGo 中配置自己的 GitHub 图床（仓库、分支、上传路径和访问令牌），使用唯一文件名；输出地址应为 `https://raw.githubusercontent.com/用户/仓库/分支/图片路径`。Obsidian 通过你选用的图片上传插件调用 PicGo，将标准 Markdown 图片链接写进文章。PicGo/Obsidian 属于写作端，需要在其应用中配置，本项目不会安装或自动配置它们。

文章放入 `src/content/` 后正常暂存并提交。提交钩子读取暂存版本，自动完成下载、WebP 转换、R2 上传、公开地址校验和映射表暂存；失败会阻止提交。文章源文件保留 GitHub 原图地址，Astro 发布时替换为 `assets.charlore.cn` 地址。部署端无需 R2 密钥。

- `pnpm images:check`：验证连接，统计桶内 JPG/PNG。
- `pnpm images:migrate-r2`：分页处理桶内 JPG/PNG，保留原文件。尝试无损 WebP（保留尺寸、ICC 配置并修正方向），逐张核对解码像素。只有 WebP 严格小于原图才使用，否则继续使用原 JPG/PNG。GitHub 新图片采用同一规则，转换无收益时将原图原样上传 R2。已有有损映射从原图重新生成。
- `pnpm images:sync`：扫描所有文章的 GitHub Raw 图片，包括正文引用式图片和封面字段。
- `git config core.hooksPath .githooks`：每台电脑配置一次。提交时仅扫描暂存文章，迁移失败阻止提交；无新图片时不需要 R2 凭据。

每张图片上传后校验公开地址的 SHA-256，成功才写映射。已有 R2 图片按 ETag 跳过；GitHub 图床图片应使用唯一文件名，不在相同 URL 覆盖原图。映射表与文章一起提交。手动迁移后需一并提交映射表；部分失败时已成功的映射保留，可用手动同步命令恢复。

Astro 正文插件、文章封面字段和站点图片配置读取映射，原文章 URL 保留。MDX 动态表达式、自定义组件的图片参数不在自动扫描范围；标准 Markdown 图片和 HTML img 字面量受支持。不会自动删除 R2 旧图片，也不会自动发布网站。

初次设置完成后，将自动化代码和映射表一并提交。若映射表有尚未暂存的编辑且本次出现新图片，钩子会提示先审阅并暂存映射表，避免自动暂存无关修改。
